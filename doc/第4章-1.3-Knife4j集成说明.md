# 第4章 1.3：Knife4j 集成说明

## 文档来源与范围

已通过浏览器实际读取[飞书第4章正文](https://rant7bdsfuy.feishu.cn/wiki/XB9swBlJritgCUkZQECcOzqlnjg)，页面标记为互联网公开，无需登录。1.3 节指向[若依 Knife4j 集成指南](https://doc.ruoyi.vip/ruoyi-vue/document/cjjc.html#集成knife4j实现swagger文档增强)，要求接入在线接口 UI，并配置登录 Token 进行受保护接口的调试。

本次实现 1.3 集成；后续章节的注解补充、统一泛型返回值和代码生成模板改造不属于本次实现范围。下文业务接口与字段来自当前项目 Controller、实体及 Mapper；1.3 节本身没有定义新的业务接口或建表 SQL。

## 功能需求

- 打开 `/doc.html` 查看 Knife4j，支持浏览接口路径、请求参数、响应结构、在线调试和离线文档导出。
- 将现有接口分为“系统接口”和“护理平台”，护理分组覆盖护理项目、护理计划、护理等级。
- 文档页面和资源可匿名读取；业务接口继续校验 JWT 和 `@PreAuthorize` 权限。
- 从正常登录结果取得 Token，在文档全局认证中填写 `Bearer <token>`，供后续请求携带。

## 对应项目版本的实现

| 组件 | 当前版本/方案 |
| --- | --- |
| Java | 21 |
| Spring Boot | 4.1.0，保持现有版本 |
| springdoc | 3.1.0，保持现有版本并继续生成 OpenAPI |
| Knife4j | `com.github.xiaoymin:knife4j-openapi3-ui:4.4.0` |
| OpenAPI 输出 | `OPENAPI_3_0`，避免旧 UI 对 3.1 Schema 的兼容问题 |

采用纯 UI 依赖，[Knife4j 官方版本说明](https://doc.xiaominfo.com/docs/quick-start/start-knife4j-version)明确允许纯 UI 与不同 Spring Boot 版本配合使用。课程里的 Springfox 和 Boot 2 starter、若依参考中的 Boot 3 starter 均不直接套入 Boot 4 项目，避免传递引入旧版 springdoc/自动配置。

根 `pom.xml` 管理 Knife4j 版本，`zzyl-admin` 引入 UI。`ResourcesConfig` 注册页面和 webjars 资源，并移除原先指向 Springfox 的旧 Swagger UI 资源映射；Swagger UI 由 springdoc 自动配置。`SecurityConfig` 允许读取 Knife4j 静态资源。`application.yml` 配置接口分组，`SwaggerConfig` 复用原有 Authorization 全局认证方案并补充调试说明。

纯 UI 方案不加载 Knife4j 服务端增强配置，因此不配置 `knife4j.enable`、`knife4j.basic`、`knife4j.production`；接口说明仍使用 OpenAPI 3 注解体系。

## 接口设计

### 文档和认证入口

默认端口为 8080，若启动时覆盖端口，以实际端口为准。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/doc.html` | Knife4j 入口 |
| GET | `/webjars/**` | Knife4j 脚本、样式等资源 |
| GET | `/v3/api-docs/swagger-config` | UI 获取分组配置 |
| GET | `/v3/api-docs/default` | 系统接口定义 |
| GET | `/v3/api-docs/nursing` | 护理平台接口定义 |
| GET | `/v3/api-docs` | 默认完整接口定义 |
| GET | `/swagger-ui.html` | 保留的 Swagger UI 入口 |
| POST | `/login` | 现有登录接口，返回业务 Token |

业务请求头：`Authorization: Bearer <token>`。当前 OpenAPI 安全方案类型为 APIKEY，UI 中须填写包含 `Bearer ` 前缀的完整值。未登录或 Token 失效时，认证失败响应体的 `code` 为 401；还需拥有对应操作权限。

### 已有护理业务接口

三类资源前缀分别为 `/nursing/project`、`/nursing/plan`、`/nursing/level`，均提供以下接口：

| 方法 | 前缀后的路径 | 请求 | 响应 | 权限后缀 |
| --- | --- | --- | --- | --- |
| GET | `/list` | 查询条件及 `pageNum`、`pageSize` | `TableDataInfo`：`rows`、`total`、`code`、`msg` | `list` |
| GET | `/{id}` | 路径参数 id | `AjaxResult`：实体放在 data 中 | `query` |
| POST | 空 | JSON 实体 | `AjaxResult` | `add` |
| PUT | 空 | JSON 实体，包含 id | `AjaxResult` | `edit` |
| DELETE | `/{ids}` | 逗号分隔的 ID | `AjaxResult` | `remove` |
| POST | `/export` | 查询条件 | Excel 文件 | `export` |

权限格式如 `nursing:project:list`、`nursing:plan:query`、`nursing:level:export`。接口契约保持现有实现，未执行增删改接口验证。

## 数据库结构

1.3 是接口文档 UI 集成，无新增表、字段或数据迁移。

以下是当前实体与 Mapper 确认的逻辑字段，类型列为 Java 类型。仓库未提供护理表建表 DDL，不能据此确定数据库列长度、精度、索引、非空或外键约束。

| 表 | 业务字段（数据库列 → Java 类型） |
| --- | --- |
| `nursing_project` | `id → Long`，`name → String`，`order_no → Integer`，`unit → String`，`price → BigDecimal`，`image → String`，`nursing_requirement → String`，`status → Integer` |
| `nursing_plan` | `id → Long`，`sort_no → Integer`，`plan_name → String`，`status → Integer` |
| `nursing_level` | `id → Long`，`name → String`，`plan_id → Long`，`fee → BigDecimal`，`status → Integer`，`description → String` |

三表均映射 `create_time`、`update_time`、`create_by`、`update_by`、`remark` 公共字段。状态值在实体注释中定义为 0 禁用、1 启用。`nursing_level.plan_id` 在实体中表示护理计划 ID；是否存在数据库外键约束需以真实 DDL 为准。

## 使用步骤

1. 在项目根目录执行 `mvn -pl zzyl-admin -am package "-Dmaven.test.skip=true"`。
2. 使用项目现有 MySQL、Redis 配置启动 `zzyl-admin/target/zzyl-admin.jar`。
3. 访问 `http://localhost:8080/doc.html`，切换“护理平台”，查看三个护理控制器的接口。
4. 正常登录系统，在登录响应或浏览器网络面板取出 Token，填入 Knife4j 的全局认证 `apikey` 中，值为 `Bearer <token>`。
5. 使用有查询权限的账号调用护理列表接口，确认返回 rows 和 total。Token 失效时重新登录并更新认证值。

当前仓库没有前端工程，若需把前端“系统工具 / 系统接口”菜单切到 Knife4j，应在对应前端仓库将 iframe 地址改为后端地址加 `/doc.html`。

## 实际验证结果

- 八个 Maven 模块编译打包成功；上述命令跳过测试，没有将其作为单元测试通过的结论。
- 在 `127.0.0.1:18080` 临时启动打包后的完整应用；验证后关闭该验证进程。
- `/doc.html`、页面 JS、`/v3/api-docs/swagger-config` 及两个分组的 OpenAPI JSON 均返回 HTTP 200。
- 浏览器实际渲染成功，护理分组展示 18 个操作（POST 6、PUT 3、GET 6、DELETE 3）；Authorize 页面存在 `apikey / Authorization / header` 输入。
- 匿名请求 `/nursing/project/list` 返回现有认证失败响应（HTTP 200，JSON `code: 401`）。未进行真实账号登录及带 Token 的业务调用，也未执行增删改或导出。
- 打包产物保留 springdoc 3.1.0，仅新增 Knife4j UI 4.4.0，没有引入 Springfox 或 Knife4j 服务端 starter。

本机启动时遇到 JDK 的 `Unable to establish loopback connection` / `UnixDomainSockets` 错误，Redis 初始化因此失败。指定一个存在的纯英文临时目录后完整应用成功启动。本次仅对验证进程加了如下 JVM 参数，没有修改项目或系统环境：

```powershell
New-Item -ItemType Directory -Force -Path zzyl-admin/target/uds | Out-Null
java "-Djdk.net.unixdomain.tmpdir=D:/java-Develop/Web-study/Test/zzyl/zzyl-admin/target/uds" -jar zzyl-admin/target/zzyl-admin.jar --server.address=127.0.0.1 --server.port=18080 --spring.quartz.auto-startup=false
```

路径需随项目位置调整。该参数仅用于有上述临时目录问题的环境；正常启动环境无需添加。验证进程关闭了 Quartz 自动启动，避免执行定时业务任务。
